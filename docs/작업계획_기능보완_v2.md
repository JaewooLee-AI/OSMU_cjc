## 요청 1 — 대시보드 상태판 클릭 시 이동

**현재 구조**: [dashboard_view.py](../flet_app/views/dashboard_view.py)는 보기 전용입니다. 다른 화면에서 워크벤치로 글을 넘기는
연결(`state.pending_workbench_campaign_id` + `state.navigate_to_workbench`)은 이미 뉴스 큐레이션이 쓰고 있습니다.

| 항목 | 분류 | 구현 |
|---|---|---|
| 소재 대기·생성 중·초안·게시 대기 글 제목 → 워크벤치에서 그 글 열기 | ✅ | 위 연결을 그대로 사용 |
| 통계 카드(작업 중·초안 완료·게시 완료) → 그 상태의 글만 목록에 표시 | ✅ | 대시보드 안 필터 상태. 같은 카드를 다시 누르면 전체 |
| 게시 완료 글 제목 → 실제 네이버 글 열기 | ✅ | `campaigns.published_url` 추가. [✅ 수동으로 완료] 때 주소를 붙여 넣고, 게시 완료 카드에서 나중에 고칠 수 있음. 주소가 없으면 워크벤치(읽기용)로 엶 |
| 네이버 [발행] 뒤 글 주소 자동 기록 | ⚠️ | 자동화는 [발행]을 누르지 않으므로(사람이 누름), 게시 창이 열려 있는 동안 Chrome 주소가 `blog.naver.com/{아이디}/{글번호}`로 바뀌는지 지켜보고, 바뀌면 주소를 저장하고 게시 완료로 바꿉니다. **실제 네이버 계정에서만 확인 가능** (로컬 검증) |

## 요청 2 — 콘텐츠 캘린더 및 작성 예약

**DB**: `campaigns`에 `scheduled_date`(발행 예정일), `published_at`(게시 처리 시각), `series_name`(시리즈 이름),

`schedule_rules`(반복 규칙: 요일·킷·모드·제목 틀).

| 항목 | 분류 | 구현 |
|---|---|---|
| 새 메뉴 📅 캘린더 — 월간 달력, 이전·다음 달, 브랜드 킷 필터 | ✅ | 새 화면 `calendar_view.py` |

| 칩 클릭 → 워크벤치에서 그 글 열기 | ✅ | 요청 1과 같은 연결 |
| 발행 예정일 등록 — 워크벤치 상단 날짜 선택, 캘린더 빈 날짜 클릭 | ✅ | 빈 날짜를 누르면 "새 글 만들기 / 예정일 없는 글 지정 / 주제 배치" |
| 지연 표시 — 예정일이 지났는데 게시 안 된 글 | ✅ | 칩에 ⚠️ + 빨간 테두리, 상단에 지연 건수 |

## 요청 3 — 토큰 사용금액 환산 누적 표시

**현재 구조**: 모든 LLM 호출이 `usage_log`에 벤더·모델·입력/출력 토큰을 남깁니다([multi_llm_router.py](../ai_workers/multi_llm_router.py)).
값은 벤더가 응답에 준 **실제 사용량**이고, 사용량을 주지 않은 응답만 글자 수로 추정합니다.
단, Anthropic의 캐시 읽기·쓰기 토큰이 일반 입력에 **합쳐져** 기록되고, 어느 글의 호출인지는 기록되지 않습니다.

**DB**: `usage_log`에 `campaign_id`, `cached_input_tokens`, `cost_usd`(호출 시점 단가로 계산, 단가 미등록이면 비움) 추가.
새 테이블 `model_prices`(벤더·모델·100만 토큰당 입력/출력/캐시 입력 단가 USD). 환율·월 예산은 `app_state`.

| 항목 | 분류 | 구현 |
|---|---|---|
| 단가 표 — 벤더·모델별 입력·출력 단가 직접 입력, 공식 가격 페이지 링크 | ✅ | ⚙️ 설정 → 📈 사용량 탭. **기본 단가는 넣지 않습니다**(가격은 자주 바뀌고, 지어낸 값이 들어가면 안 됨) |
| 이미지 분석은 입력 토큰으로 계산 | ✅ | 사진 분석 호출도 같은 표로 계산 |
| 환율(USD→KRW) 설정, 원화·달러 함께 표시 | ✅ | 기본값 1,400원 — **실제 환율로 고쳐 쓰라는 안내와 함께** |
| 오늘·이번 달·전체 누적 금액 카드 | ✅ | |
| 벤더·모델별 표(호출 수·입력·출력·금액) | ✅ | |
| 글 1건당 평균 금액 | ✅ | 전체 금액 ÷ 생성 완료된 글 수 |
| 워크벤치 "이 글 생성 비용 약 ○○원" | ✅ | 이번 생성 실행에서 그 글로 기록된 호출만 합산 |
| 월 예산 경고 70%·90% | ✅ | 대시보드·워크벤치·사용량 탭에 안내. 생성을 막지는 않음 |
| 단가 미등록 모델은 "단가 미등록", 0원으로 세지 않음 | ✅ | |
| 단가를 바꿔도 과거 기록은 그대로 | ✅ | 금액을 호출 시점에 계산해 저장 |
| 기존 기록을 현재 단가로 한 번 채우기 | ✅ | 단가를 처음 저장할 때 그 모델의 "금액 없음" 기록만 채움 |
| 대시보드 "절감된 토큰"을 금액으로 | ⚠️ | 절감 토큰 자체가 추정치(캐시 적중·축소로 **안 쓴** 양)라 금액도 추정입니다 |
| 캐시 토큰(cache_read 등) 별도 단가 | ⚠️ | 앞으로의 기록부터 캐시 토큰을 따로 남기고, 캐시 단가를 입력하면 그 단가로 계산(비우면 일반 입력 단가 + 표시) |
| 과거 기록의 글별 비용, 과거 캐시 토큰 분리 | ❌ | 예전 기록에는 글 ID와 캐시 구분이 없어 나눌 수 없습니다 — 앞으로의 기록부터 정확 |
| 표시 금액이 추정값이라는 안내 | ✅ | "예산 참고용 추정값 — 실제 청구는 각 벤더 콘솔에서 확인" |

## 요청 4 — 원고 디자인 요소 (텍스트 서식 · 인용구 · 구분선)

**현재 구조와 충돌**: 원고는 처음부터 끝까지 **평문**입니다. 생성 프롬프트가 "마크다운 기호를 쓰지 말라"고 하고,
그 뒤 단계들(컴플라이언스 문구 교체, SEO 키워드 보정, 맞춤법 교정, 글자 수·키워드 밀도 측정, 유사문서 비교,
인스타·X·쇼츠 변환)이 모두 평문을 전제로 돕니다. 서식 기호를 본문에 섞으면 이 단계들이 기호를 깨뜨리거나
교정 문구를 못 찾게 됩니다. 또 [작업계획_멀티브랜드킷.md](작업계획_멀티브랜드킷.md) **결정 3**은
"네이버 에디터 세부 서식(인용구·구분선 등)은 툴바를 자동으로 누르지 않는다"입니다.

**설계 — 서식 레이어**
- 본문(`content`)은 지금처럼 평문으로 둡니다. 서식은 `campaigns.content_format`(JSON)에
  "어느 문장을 굵게 / 어느 문단을 인용구로 / 어느 문단 앞에 구분선" 식으로 **문장에 붙은 표시**로 따로 저장합니다.
- 초안을 쓰는 **같은 호출**에서 서식 기호까지 받고(토큰 추가 거의 없음), 받자마자 기호를 떼어 서식 레이어로 옮깁니다.
  그래서 검수·SEO·교정·SNS 단계는 하나도 바뀌지 않고, 컴플라이언스 감사도 서식 없는 본문 그대로 검사합니다.
- 미리보기와 네이버 붙여넣기 때만 서식을 입힙니다. 교정 단계에서 문장이 바뀌어 붙일 자리를 못 찾은 서식은 버리고,
  미리보기에 "적용 안 된 서식 N개"로 알립니다(틀린 자리에 붙이는 것보다 안전).
- 네이버에는 지금처럼 **클립보드 붙여넣기**로만 넣습니다(HTML에 서식을 담음). 툴바는 누르지 않으므로 결정 3을 지킵니다.

| 항목 | 분류 | 구현 |
|---|---|---|
| 핵심 문장 굵게·형광 표시, 문단당 1~2곳 제한 | ✅ | 강조 개수를 코드로 다시 잘라 냄 |
| 소제목(H2·H3) 구분 | ✅ | |
| 글머리·번호 목록 | ✅ | 목록은 평문에도 자연스러워 본문에 `- ` / `1. `로 남김 |
| 인용구 블록(글당 1~2개) | ✅ | |
| 구분선(도입-본문-마무리, 주제 전환) | ✅ | |
| 글 끝 '핵심 정리' 박스·체크리스트 | ✅ | 본문 문장이므로 검수를 그대로 받음 |
| 이미지 자리·캡션 제안 | ✅ | 사진이 없는 글에도 "여기에 ○○ 사진" 제안을 서식 레이어에 둠. 네이버에는 눈에 띄는 안내 줄로 들어가 발행 전에 지우도록 경고 |
| 디자인 템플릿(기본형·정보형·후기형), 킷 설정에 저장 | ✅ | `brand_kit.design_template`·`design_strength` |

| 글 길이에 따른 상한 | ✅ | 강도·글 길이로 인용구·구분선·강조 최대 개수 계산 |

### 결정·구현 메모

- **결정 3(툴바 자동화 안 함)은 유지합니다.** 서식은 붙여넣는 HTML에만 담고, 붙인 뒤 에디터에 인용구·구분선·표 요소가
  생겼는지 **세기만** 합니다. 그래서 인용구·구분선 **모양 선택**은 자동화하지 않습니다(❌).
- [서식 적용]은 이미 있는 짧은 문단만 소제목으로 만들 수 있습니다 — 새 소제목 문장을 만들면 검수를 거치지 않은 글자가 생기기 때문입니다.
- 사진이 첨부된 글은 사진 자리 제안 대신 `[사진 설명]`(네이버 사진 설명 칸에 붙일 문구)을 받습니다. 설명 칸 입력은 사진을
  하나씩 눌러야 해서 자동으로 넣지 않고 게시 화면에서 복사하게 했습니다.
- 초안을 만든 뒤 사진을 올리면 '사진 자리' 표시가 있던 곳에 차례로 넣고 그 표시를 지웁니다(`formatting.fill_photo_hints`,
  AI 호출 없음). 본문에 배치되지 않은 첨부 사진은 [지금 게시] 때 글 끝에 붙습니다 — 예전에는 미리보기에만 글 끝에
  보이고 실제 게시에서는 빠졌습니다(이번 작업 전부터 있던 차이).
- 반복 규칙은 화면을 열 때마다 자리를 만들지 않습니다 — 담당자가 지운 자리가 되살아나지 않게, 규칙 추가 때와 버튼을 누를 때만.
- 기본 단가는 넣지 않았습니다(사실을 지어내지 않음). 환율 기본값 1,400원은 "고쳐 쓰라"는 안내와 함께 둡니다.
- 서식 강도의 킷 기본값은 **표준**입니다. 기존 설치의 '기본' 킷도 마이그레이션으로 '표준·기본형'이 되므로, 다음 생성부터
  서식이 들어갑니다. 원하지 않으면 브랜드 킷에서 '사용 안 함'으로 바꿉니다.
