# 작업 계획 — 📦 데이터 옮기기 (담당자 PC 사이)

같은 엔진을 쓰는 OSMU_osw에 2026-10-21 들어간 기능(커밋 `7029384`, "담당자 PC 사이에 브랜드 킷·API 키·키워드 측정값을
옮기는 📦 데이터 옮기기")을 이 앱으로 옮겼습니다 (2026-10-23, 브랜치 `feature/data-transfer`).

## OSMU_osw의 기능

- 화면: ⚙️ 설정 → 📦 데이터 옮기기 탭. [📤 파일로 내보내기] / [📂 .osmu 파일 열기] → [📥 이 PC에 가져오기].
- 항목 3개: 브랜드 킷(한 줄짜리 킷 — 회사 정보·모델 선택 포함), API 키(LLM·네이버 API HUB·검색광고), 키워드 측정값.
- API 키는 내보내는 사람이 정한 비밀번호(6자 이상)로 PBKDF2-HMAC-SHA256(390,000회) → AES-256-GCM 암호화. 가져올 때
  받는 PC의 마스터 키로 다시 암호화. 틀린 비밀번호면 아무것도 바꾸지 않음.
- 받는 PC의 글·사진·게시 기록·네이버 로그인은 건드리지 않음. 측정값은 받는 PC에 더 최근 값이 있으면 유지.
- 키만 가져왔고 받는 PC에 기본 생성 모델이 없으면 보낸 PC의 선택을 따름.
- 파일: `core/transfer.py`, `flet_app/views/settings_view.py`(`_build_transfer_tab`), `tests/test_transfer.py`, README 한 단락.

## 이 앱에서 달라진 점

| | OSMU_osw | 이 앱 |
|---|---|---|
| 브랜드 킷 | 한 줄을 통째로 덮어씀 | 보관하지 않은 킷 전부. **킷 이름으로 맞춤** — 같은 이름은 내용을 바꾸고 없으면 새로 만듦. 킷 ID는 받는 PC 것을 유지(글·주제·반복 규칙이 킷 ID를 들고 있음). 받는 PC에만 있는 킷은 그대로 |
| 회사 공통·앱 설정 | 킷에 포함 | 따로 고르는 항목(`company_profile`·`app_settings`·네이버 서식 방식). 받는 PC에 키가 없는 벤더로 모델 선택을 바꾸지 않음 |
| AI 비용 설정 | 없음 | 단가(`model_prices`)·환율·월 예산. 받는 PC의 '단가 미등록' 기록을 받은 단가로 채움(설정에서 단가를 저장할 때와 같음) |
| 제목 이력 | 없음 | 같은 블로그를 여러 PC가 쓰므로 옮길 수 있게 함. 이미 있는 제목은 건너뜀, 글 ID 태그는 뺌 |
| 가져오기 | 항목마다 따로 저장 | **한 트랜잭션** — 중간에 실패하면 아무것도 바뀌지 않음. 바꾸기 직전 DB를 데이터 폴더 `backups/`에 복사(최근 5개) |
| 파일 형식 | `osmu-transfer` | `osmu-cjc-transfer` — 다른 회사용 앱의 파일은 "다른 회사용 OSMU 앱에서 만든 파일입니다"로 거절 |
| 빠짐 방지 | — | `transfer.TABLE_PARTS`에 DB의 모든 테이블을 적고, 시험이 실제 테이블 목록과 같은지 확인 |

## 테이블·파일별 결정

| 대상 | 항목 | 이유 |
|---|---|---|
| `brand_kit` | 브랜드 킷 | 보관한 킷은 제외 |
| `company_profile`, `app_settings` | 회사 공통·앱 설정 | |
| `app_state.naver_format_mode` | 회사 공통·앱 설정 | |
| `app_state.usd_krw`, `usage_budget` | AI 비용 설정 | |
| 그 밖의 `app_state` (`sweep:{킷 ID}`, `category_sweep:{킷 ID}`, `settings_keyword_kit`, `ui_font_scale`, `brand_seed_fixes_applied`) | 옮기지 않음 | 킷 ID가 PC마다 다르고, 진행 중 작업·화면 취향·그 PC의 시드 적용 기록 |
| `llm_settings`, `naver_api_settings`, `searchad_settings` | API 키 | 비밀번호로 암호화 |
| `model_prices` | AI 비용 설정 | |
| `keyword_cache` | 키워드 측정값 | 더 최근 값 유지 |
| `title_history` | 제목 이력 | |
| `campaigns` | 옮기지 않음 | 글·서식(`content_format`)·캘린더 일정(`scheduled_date`·`auto_generate_at`)·게시 기록(`published_url`) — 받는 PC의 작업 |
| `assets` + `assets/` 폴더 | 옮기지 않음 | 사진은 그 PC의 글에 붙음 |
| `vision_cache` | 옮기지 않음 | 그 PC의 사진 분석 결과 |
| `topics`, `schedule_rules` | 옮기지 않음 | 받는 PC의 글·킷 ID에 연결됨 (아래 '다음에 할 수 있는 것') |
| `usage_log`, `naver_api_calls` | 옮기지 않음 | 그 PC에서 쓴 비용·호출 기록 |
| `.master_key` | 절대 옮기지 않음 | 키는 비밀번호로 다시 암호화해 옮김 |
| `naver_state.json` | 옮기지 않음 | 네이버 로그인 세션 — PC마다 로그인 |

PC를 통째로 바꿀 때(글·사진까지)는 이 기능이 아니라 앱을 닫고 데이터 폴더 전체를 복사합니다(화면·매뉴얼에 안내).
