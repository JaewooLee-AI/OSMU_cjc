# 고객 전달 전 테스트 — 씨제이씨협동조합 OSMU 워크벤치

> 작성 2026-10-17 · 대상: 멀티 브랜드 킷(작업 2) + setup.exe 설치 프로그램(작업 3)이 들어간 첫 고객 배포
> 이 문서대로 시험하고 결과를 맨 아래 **결과 기록표**에 적은 뒤 고객에게 전달합니다.
> 공개 저장소이므로 API 키·고객 데이터·실제 글 내용은 이 문서나 결과 기록표에 적지 않습니다.

## 이미 확인된 것 (다시 하지 않아도 됨)

| 범위 | 확인 방법 | 결과 |
|---|---|---|
| DB 마이그레이션, 킷 추가(분야별 프리셋/복사)·복제·이름 변경·삭제·되살리기, 화면 생성 | 클라우드 자동 시험(LLM 없이) + 로컬 DB 검증 | 통과 |
| 각 화면 클릭, 브랜드 킷 대화상자 | 개발자 Windows, 브랜치 빌드 #21 exe | 정상 |
| 실제 데이터 복사본 마이그레이션, 킷별 생성(실제 LLM), 제목 키워드, 키워드 작업 킷 반영, 네이버 게시 자동 입력 | 개발자 Windows | 정상 |
| **고객 지정 멀티 LLM 연동 (`claude-sonnet-5-5` 글 생성 + `gemini-3.8-flash` 이미지 분석)** | 실제 API E2E 호출 시험 (모델명 정규화·토큰 한도 여유분·콘텐츠 해시 캐시 적중 확인) | **통과** |
| **멀티 브랜드 킷 사업 분야 간 내용 혼입 방지 검증 (B2C 가발 관리 vs B2B 창업·OEM)** | 분야별 프리셋 킷 2개로 연속 생성 후 타 분야 키워드·문장 혼입률(0%) 및 의료법 가드레일(93점·95점) 검증 | **통과 (혼입 0건)** |
| 설치 → 재설치 → 제거, 옛 파일 정리, 아이콘·"설치된 앱" 항목 1개, `%APPDATA%\OSMU_CJC` 보존 | GitHub Actions 러너에서 매 빌드 자동 실행 | 빌드 결과로 확인 |

아래는 **사람이 실제 Windows에서 고객과 같은 방식으로** 해 봐야 하는 것만 모았습니다.

## 0. 준비

- [ ] **시험할 파일**: 고객이 받을 것과 **같은 파일**로 시험합니다.
  1. 먼저 브랜치 빌드(Actions → `flet-windows-build` → 해당 실행 → `osmu-cjc-setup` artifact)로 1~9를 시험합니다.
  2. 통과하면 `feature/multi-brand-kit`을 `main`에 합칩니다(PR). **main에 합치면 Release가 자동 게시**되어
     고객이 받는 `releases/latest` 주소가 바로 바뀝니다 — 그 전에 1~9가 통과해야 합니다.
  3. Release에 올라간 `OSMU-CJC-Setup-v0.1.N.zip`으로 **10. 최종 확인**만 한 번 더 합니다.
- [ ] **시험 PC 두 대(또는 두 상태)**
  - A: 이 앱을 한 번도 설치하지 않은 PC (또는 `%APPDATA%\OSMU_CJC`를 다른 곳으로 옮겨 둔 상태) — "새 고객" 역할
  - B: 예전 zip 버전을 쓰던 PC (고객 PC와 같은 상황) — "기존 고객" 역할
- [ ] **B의 데이터 백업**: 시험 전에 `%APPDATA%\OSMU_CJC` 폴더를 통째로 다른 곳에 복사해 둡니다(문제가 생기면 되돌리기용).
- [ ] **키**: LLM API 키 1개, 네이버 API HUB 키, 검색광고 API 키 (화면에 직접 입력. 파일·메신저에 붙여 두지 않기)
- [ ] **네이버 계정**: 시험용으로 써도 되는 블로그 (실제 발행은 하지 않고 [발행] 직전까지만 확인)
- [ ] 윈도우 버전 기록 (예: Windows 11 23H2 / Windows 10 22H2)

## 1. 전달·설치 (고객이 처음 하는 일) — 필수

| # | 할 일 | 통과 기준 |
|---|---|---|
| 1-1 | zip을 **카카오톡 PC**로 다른 계정에 보내고, 받는 쪽에서 내려받기 | 차단·경고 없이 받아짐 (zip 안에 exe가 들어 있어도 막히지 않는지) |
| 1-2 | zip 압축 풀기 (탐색기 [압축 풀기]) | 안에 `OSMU-CJC-Setup-0.1.N.exe` **하나만** 있음 |
| 1-3 | setup.exe 더블클릭 | "Windows의 PC 보호"(SmartScreen) → [추가 정보] → [실행]으로 넘어감. 이 화면은 매뉴얼 4쪽 안내와 같음 |
| 1-4 | 관리자 권한 확인(UAC) [예] | 설치 화면이 **한국어**로 나옴 |
| 1-5 | 설치 진행 → 마침 | 오류 없이 끝남. "실행" 체크 상태로 마치면 앱이 바로 열림 |
| 1-6 | 바탕화면·시작 메뉴 확인 | "씨제이씨협동조합 OSMU 워크벤치" 아이콘이 둘 다 있고 **씨제이씨 로고**로 보임 |
| 1-7 | 설치 폴더 확인 | `C:\Program Files\OSMU CJC`에 설치됨 |
| 1-8 | 앱 실행 | 창 제목·작업 표시줄 아이콘이 로고, 🧵 브랜드 킷 화면이 '기본' 킷으로 열림 (A는 조합 자료가 채워진 상태) |
| 1-9 | Windows 설정 → 앱 → 설치된 앱 | "씨제이씨협동조합 OSMU 워크벤치"가 **하나만** 있음 |

## 2. 기존 고객 이관 (PC B) — 필수

| # | 할 일 | 통과 기준 |
|---|---|---|
| 2-1 | 예전 zip 버전을 종료하고, 예전 폴더는 **지우지 않은 채** setup.exe 설치 | 설치 정상 |
| 2-2 | 바탕화면 새 아이콘으로 실행 | 기존 글·사진·SEO 키워드·브랜드 킷 내용이 그대로 있음. 기존 킷 이름은 **'기본'** |
| 2-3 | ⚙️ 설정 | LLM·네이버 API 키가 "✅ 등록됨"으로 남아 있음 (다시 입력하지 않아도 됨) |
| 2-4 | 🚀 네이버 게시 | 네이버 로그인 상태가 유지됨. 기존 글 카드에 "🧵 브랜드 킷: 기본" 표시 |
| 2-5 | 예전 zip 폴더 삭제 후 새 아이콘으로 다시 실행 | 여전히 같은 데이터 (예전 폴더를 지워도 된다는 안내가 맞는지) |
| 2-6 | 톤앤매너 마지막 줄 확인 | "매 글 끝에 … 창업 교육 문의 …"가 "글 주제가 … 직접 이어질 때에만 …"으로 바뀌어 있음 (그 줄을 직접 고친 적이 있다면 고친 그대로) |

## 3. 업데이트·재설치 — 필수

| # | 할 일 | 통과 기준 |
|---|---|---|
| 3-1 | 앱을 **켜 둔 채로** 같은 setup.exe 다시 실행 | 앱이 자동으로 닫히고 설치가 끝남 (파일 사용 중 오류 없음) |
| 3-2 | 🚀 네이버 게시 [지금 게시]로 Chrome 자동 입력 창을 띄운 채 setup.exe 실행 | 자동 입력 Chrome 창까지 닫히고 설치가 끝남. **직접 켜 둔 다른 Chrome 창은 그대로** |
| 3-3 | 재설치 후 실행 | 데이터·키·로그인 그대로, 바탕화면 아이콘 **1개**, "설치된 앱" 목록 **1개** |
| 3-4 | (가능하면) 다음 빌드 번호의 새 setup.exe로 덮어쓰기 | 3-3과 같음, "설치된 앱"의 버전이 새 번호 |

## 4. 제거 — 필수

| # | 할 일 | 통과 기준 |
|---|---|---|
| 4-1 | Windows 설정 → 앱 → 설치된 앱 → 제거 | 오류 없이 끝남. 바탕화면·시작 메뉴 아이콘과 `C:\Program Files\OSMU CJC`가 사라짐 |
| 4-2 | `%APPDATA%\OSMU_CJC` 확인 | **그대로 남아 있음** (osmu.db, assets, .master_key, naver_state.json) |
| 4-3 | 다시 설치 후 실행 | 제거 전 데이터·키·로그인이 그대로 이어짐 |

## 6. 첫 설정 (새 고객 PC A) — 필수

매뉴얼 ① 설치와 초기 설정 순서 그대로 따라 합니다. **매뉴얼만 보고 막힘 없이 되는지**가 기준입니다.

- [ ] LLM 벤더 1개 [연결 테스트 · 저장] → 성공 배지, 기본 생성 모델로 자동 지정
- [ ] 네이버 API HUB 키, 검색광고 API 키 저장 → 각각 "✅ 등록됨"
- [ ] 글자 크기 조정이 다시 열어도 유지됨

## 7. 브랜드 킷 (고객이 직접 관리할 부분) — 필수

| # | 할 일 | 통과 기준 |
|---|---|---|
| 7-1 | [➕ 새 킷 만들기] → 이름 "가발 판매·관리" | '기본' 킷 내용이 복사된 새 킷이 생기고 그 킷 편집 화면으로 바뀜 |
| 7-2 | 업종·페르소나·SEO 키워드를 그 분야에 맞게 고치고 [킷 저장] | 저장 메시지. 다른 킷 내용은 바뀌지 않음 |
| 7-3 | 같은 이름으로 또 만들기, 빈 이름으로 만들기 | 각각 "이미 있습니다", "킷 이름을 입력해주세요" 안내, 만들어지지 않음 |
| 7-4 | [📄 복제], [이름 변경] | 복제본 이름이 "… 복사본", 이름 변경이 목록·워크벤치 선택 칸에 반영 |
| 7-5 | 회사 공통에서 금기어 한 쌍 추가 → [회사 공통 저장] | **모든 킷**에 적용됨 (8-4에서 확인) |
| 7-6 | 아직 게시하지 않은 글이 있는 킷 [🗑️ 삭제] | 글을 옮길 킷을 고르기 전에는 [삭제]가 눌리지 않음. 옮기면 그 글의 킷이 바뀜 |
| 7-7 | 아래 "삭제한 킷"에서 [↩️ 되살리기] | 다시 목록에 나옴. 같은 이름 킷이 생겼으면 "(되살림)"이 붙음 |
| 7-8 | 킷이 하나만 남았을 때 삭제 | "마지막 남은 브랜드 킷은 삭제할 수 없습니다" |

## 8. 글 생성 — 필수 (이 배포의 목적: "다른 분야 내용이 섞인다" 해결 확인)

| # | 할 일 | 통과 기준 |
|---|---|---|
| 8-1 | 워크벤치 [➕ 새 콘텐츠] → 맨 위 킷을 "가발 판매·관리"로, 메모 "가발 세탁·보관 방법" + 사진 2장 → [🪄 초안 생성] | 네이버 본문·인스타·X·쇼츠가 생성됨. 사진이 본문에 배치됨 |
| 8-2 | 8-1 결과 읽기 | 창업 교육·가맹점 모집 이야기가 **본문 중간에 없음**. 회사 소개는 끝 한두 문장 이내. 제목에 소재와 무관한 키워드 없음 |
| 8-3 | 같은 메모로 킷만 '기본'으로 바꿔 다시 생성 | 킷을 바꾸면 "다시 생성" 안내가 뜸. 결과의 키워드·말투가 킷에 따라 달라짐 |
| 8-4 | 메모에 "탈모 완치" 같은 금기 표현을 넣어 생성 | 본문·제목·SNS에서 치환되고 컴플라이언스 검수 결과가 표시됨 (7-5의 새 금기어도 치환) |
| 8-5 | [수정 요청] 칸에 "문장을 더 짧게" → [✏️ 수정 요청해서 다시 쓰기] → [📌 이 요청을 브랜드 킷에 저장] | 그 글의 킷 톤앤매너에만 추가됨 (다른 킷에는 없음) |
| 8-6 | 본문을 손으로 고친 뒤 [📣 SNS 채널 다시 만들기 (현재 본문 기준)] | SNS가 고친 본문 기준으로 다시 만들어짐 |
| 8-7 | 생성 중 다른 화면 갔다가 돌아오기 / 생성 중 앱 종료 후 다시 실행 | 중복 생성 없음 / 그 글이 '실패'로 표시되고 다시 생성 가능 |

## 9. 뉴스·키워드·게시 — 필수 (키워드 새로 고르기는 유료 호출이 있어 선택)

|---|---|---|
| 9-1 | 📰 뉴스 큐레이션에서 킷 선택 → 검색 → [➕ 워크벤치로 보내기] | 키워드 칩이 고른 킷의 SEO 키워드. 전달된 글의 킷이 그 킷 |
| 9-2 | ⚙️ 설정 → 네이버 API → 대상 킷 선택 → 🔬 [키워드 진단 실행] | 고른 킷의 키워드만 진단됨 |
| 9-3 | (선택, 유료 호출 소량) 대상 킷에서 [➕ 사업 분야 추가] 한 번 | 결과가 그 킷의 SEO 키워드에만 들어감. 사용량 탭에 호출 수 표시 |
| 9-4 | 🚀 네이버 게시 → [네이버 로그인] → [지금 게시] | Chrome에 제목·본문·사진이 자동 입력되고 [발행] 직전에서 멈춤 (발행은 하지 않음) |
| 9-5 | [✅ 수동으로 완료] | 게시 완료 탭으로 이동, 카드에 킷 이름 표시 |

```
   예전 압축 폴더는 새 버전이 잘 열리는 것을 확인한 뒤 지우셔도 됩니다.
4) 이번 버전부터 브랜드 킷을 사업 분야별로 여러 개 만들 수 있습니다.
   글을 쓸 때 워크벤치 맨 위에서 글 주제에 맞는 킷을 골라 주세요(매뉴얼 브랜드 킷·워크벤치 쪽).
```
